📚 المحلقות التي أنشأها الطالب (الكلاسات المُنشأة)

📋 1. كلاس WorkRequest — نموذج بيانات الطلب (Data Model)

תפקיד המחלקה (تفقيد الكلاس):

يمثل هذا الكلاس كائن طلب العمل الخاص بكل موظف. يحتوي على جميع المعلومات المتعلقة بطلب الجدول الأسبوعي.

משתני מחלקה (متغيرات الكلاس):

اسم المتغيرالنوعتفقيد المتغير (الوصف)
idStringمعرف فريد لكل طلب (رقم تعريفي)
employeeNameStringاسم الموظف صاحب الطلب
employeeIdStringالرقم الوظيفي للموظف
workScheduleMap<String, bool>خريطة أيام العمل (true=يعمل، false=إجازة)
notesStringملاحظات الموظف للمدير
submittedAtDateTimeتاريخ ووقت إرسال الطلب
statusWorkRequestStatus (Enum)حالة الطلب: معلق / مقبول / مرفوض

الكود (הקוד):

class WorkRequest {
  final String id;
  final String employeeName;
  final String employeeId;
  final Map<String, bool> workSchedule;
  final String notes;
  final DateTime submittedAt;
  WorkRequestStatus status;

  WorkRequest({
    required this.id,
    required this.employeeName,
    required this.employeeId,
    required this.workSchedule,
    required this.notes,
    required this.submittedAt,
    this.status = WorkRequestStatus.pending,
  });
}

enum WorkRequestStatus { pending, approved, rejected }
⚙️ 2. كلاس WorkRequestManager — مدير الطلبات (Singleton)

תפקיד המחלקה (تفقيد الكلاس):

الكلاس المسؤول عن إدارة وتخزين طلبات العمل في الذاكرة. يعتمد على نمط Singleton مما يضمن وجود نسخة واحدة فقط في جميع أنحاء التطبيق، مما يمنع تضارب البيانات.

משתני מחלקה (متغيرات الكلاس):

اسم المتغيرالنوعالوصف
_instanceWorkRequestManager (static)النسخة الوحيدة الثابتة من الكلاس (Singleton pattern)
_requestsList<WorkRequest>قائمة خاصة (private) تحتوي على جميع الطلبات المخزنة

פעולות מחלקה (دوال الكلاس والشرح):

اسم الدالةالمعاملات (Parameters)الإرجاع (Return)الشرح
addRequest()WorkRequest requestvoidتضيف طلباً جديداً لقائمة الطلبات
updateRequestStatus()String id, WorkRequestStatus statusvoidتغير حالة طلب موجود (موافقة أو رفض) بالبحث عن المعرف
removeRequest()String idvoidتحذف طلباً محدداً من القائمة بناءً على معرفه
getPendingRequests()-List<WorkRequest>ترجع قائمة الطلبات المعلقة (status = pending) فقط
getApprovedRequests()-List<WorkRequest>ترجع قائمة الطلبات المعتمدة (status = approved) فقط

الكود (הקוד):

class WorkRequestManager {
  // Singleton Pattern: نسخة واحدة ثابتة
  static final WorkRequestManager _instance = WorkRequestManager._internal();
  factory WorkRequestManager() => _instance;
  WorkRequestManager._internal();

  // قائمة خاصة لا يمكن تعديلها من خارج الكلاس
  final List<WorkRequest> _requests = [];

  // إضافة طلب جديد
  void addRequest(WorkRequest request) {
    _requests.add(request);
  }

  // تحديث حالة الطلب (قبول / رفض)
  void updateRequestStatus(String id, WorkRequestStatus status) {
    final index = _requests.indexWhere((r) => r.id == id);
    if (index != -1) {
      _requests[index].status = status;
    }
  }

  // حذف طلب
  void removeRequest(String id) {
    _requests.removeWhere((r) => r.id == id);
  }

  // جلب الطلبات المعلقة
  List<WorkRequest> getPendingRequests() {
    return _requests.where((r) => r.status == WorkRequestStatus.pending).toList();
  }

  // جلب الطلبات المعتمدة
  List<WorkRequest> getApprovedRequests() {
    return _requests.where((r) => r.status == WorkRequestStatus.approved).toList();
  }
}
📋 3. كلاس WorkDaysPage — صفحة تحديد أيام العمل (StatefulWidget)

תפקיד המחלקה (تفقيد الكلاس):

واجهة المستخدم (UI) التي يستخدمها العامل لتحديد أيام عمله الأسبوعية وإضافة ملاحظات، ثم إرسال الطلب للمدير.

משתני מחלקה (المتغيرات الرئيسية):

اسم المتغيرالنوعالوصف
workScheduleMap<String, bool>خريطة أيام الأسبوع مع قيمة بوليانية (عمل/إجازة)
selectedEmployeeNameStringاسم الموظف المُدخَل في الحقل النصي
savedNotesStringالملاحظات المحفوظة من الموظف للمدير
_animationControllerAnimationControllerيتحكم في الحركة العامة للصفحة (fade + slide)
_pulseControllerAnimationControllerيتحكم في تأثير النبض (pulsing) للأيقونة

פעולות ראשיות (الدوال الرئيسية):

اسم الدالةالشرح
_toggleWorkDay(dayName)تعكس حالة اليوم (من إجازة إلى عمل والعكس) عند ضغط المستخدم عليه، مع تأثير اهتزاز (HapticFeedback)
_openNotesModal()تفتح نافذة حوار (Dialog) لكتابة الملاحظات وحفظها
_saveSchedule()تتحقق من صحة البيانات وتنشئ كائن WorkRequest جديد وتضيفه لـ WorkRequestManager وترسله للمدير

تدفق العملية الرئيسية _saveSchedule():

[User Presses Save Button]
↓
[Check: is employeeName empty?]
|-- YES --> Show Error SnackBar [الرجاء إدخال اسم الموظف] --> STOP
|-- NO --> HapticFeedback (heavy impact)
↓
[Create WorkRequest object with all data]
↓
[WorkRequestManager().addRequest(newRequest)]
↓
[Show Success SnackBar "تم إرسال الطلب بنجاح"]
↓
[Navigate back to Home Page]

مقتطف الكود (הקוד):

void _toggleWorkDay(String dayName) {
  setState(() {
    workSchedule[dayName] = !workSchedule[dayName]!;
  });
  HapticFeedback.selectionClick(); // تأثير اهتزاز لحظي
}

void _saveSchedule() {
  if (selectedEmployeeName.isEmpty) {
    _showErrorMessage('الرجاء إدخال اسم الموظف');
    return;
  }
  HapticFeedback.heavyImpact();

  // إنشاء طلب جديد وإرساله للمدير
  final newRequest = WorkRequest(
    id: DateTime.now().millisecondsSinceEpoch.toString(),
    employeeName: selectedEmployeeName,
    employeeId: 'EMP_${DateTime.now().millisecondsSinceEpoch}',
    workSchedule: Map.from(workSchedule),
    notes: savedNotes,
    submittedAt: DateTime.now(),
  );
  WorkRequestManager().addRequest(newRequest);
}

Future<void> addWarehouse({required String warehouseName}) async {
  try {
    await FirebaseFirestore.instance.collection('warehouses').add({
      'warehouseName': warehouseName,
      'createdAt': FieldValue.serverTimestamp(),
    });
